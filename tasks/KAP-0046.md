# Stabilize One Deep Kubernetes Effect-Gateway Beta

Status: complete. The selected v0.2 direction was one finite stabilization release around the
existing `kubernetes.set_deployment_image` capability.

Owners: [technical scope](../docs/SCOPE.md),
[KAP-0038](../docs/experiments/KAP-0038-kubernetes-effect-gateway-boundary.md),
[architecture](../docs/ARCHITECTURE.md), and [v0.2 release design](../docs/V0.2.md).

## Decision

v0.2.0 deepens exact authorization, durable attempt recording, crash recovery, receiver observation,
explicit `UNKNOWN`, signed receipts, CLI, MCP, migration, qualification, and artifact distribution.
It adds no capability, provider abstraction, resident process, hosted dependency, or production
claim.

The accepted [`docs/V0.2.md`](../docs/V0.2.md) owns the release unit, compatibility classes, package
exclusions, implementation gates, and acceptance proof.

## Rejected alternatives

- **Add another capability:** rejected because it would multiply authorization, retry, receiver, and
  receipt semantics before the first coherent beta.
- **Freeze at v0.1.1:** rejected because the implementation still had parallel lifecycle test paths,
  duplicated adapter projection, and incomplete compatibility/migration contracts.
- **Build a Kubernetes operation suite:** rejected because operation count is not module depth.
- **Add a resident process or hosted control plane to v0.2:** rejected because neither is required
  by the local beta contract.

## Acceptance

- One capability and one concrete Kubernetes adapter remain.
- KAP-0038 lifecycle and `UNKNOWN` semantics remain unchanged.
- Compatibility, migration, qualification, and distribution have direct owners.
- The release contains no resident service, hosted control plane, public provider seam, or
  production-support claim.
