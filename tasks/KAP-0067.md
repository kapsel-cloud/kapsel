# Deepen Qualification Tooling

Status: deferred behind KAP-0066 and an observed resident-product blocker. Historical qualification
script size alone does not activate this packet.

Problem: qualification manifest validation, lane orchestration, measurement normalization, privacy
checks, and evidence identity span several Python programs with dynamic cross-file loading and
repeated process helpers. The behavior is substantial but lacks one deep interface.

Contract owners: [testing](../docs/TESTING.md), [build](../docs/BUILD.md), and
[V1 technical direction](../docs/VISION.md).

Depends on: KAP-0066 and immutable retention of the accepted v0.2 qualification manifests.

## Work

- Inventory the qualification manifest schema, lane identities, bounds, normalization rules,
  invalidation rules, and closed output.
- Add one typed qualification-tooling module under `kapsel-dev` with explicit bounded inputs and
  deterministic output.
- Replace dynamic Python module loading and duplicated hashing/process behavior incrementally.
- Preserve native-host, container, fuzz, simulation, live-kind, security, privacy, and measurement
  lane separation.
- Validate historical v0.2 manifests without rewriting or reinterpreting their evidence.
- Keep product runtime and qualification implementation independent.

## Acceptance

- One interface owns manifest validation, lane selection, evidence identity, normalization, and
  closed output while individual gates retain their direct owners.
- Deleting the module would spread qualification rules back across multiple callers.
- Accepted v0.2 manifests validate unchanged and malformed/hostile fixtures retain exact rejection
  behavior.
- No qualification helper is shipped as a product runtime or promoted to a compatibility surface.
- Python files are removed only when their behavior and independent tests are fully replaced.

## Non-goals

No new product performance claim, changed budget, historical evidence rewrite, generic CI framework,
provider interface, or all-at-once language migration.

## Activation trigger

Remain deferred. Begin only if an accepted preview qualification requirement cannot be expressed or
rerun safely with the existing finite lanes after KAP-0066's smallest necessary slice. Prefer
archiving expired historical qualification machinery over porting it. Do not create a generic CI or
evidence framework.

## Residual risk

Consolidation can couple formerly independent evidence lanes or erase environment-specific failure
information. The interface must preserve lane identity and raw diagnostic locality without exposing
sensitive evidence.
