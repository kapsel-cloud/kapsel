# Deepen Release-Source Locality

Status: complete. Journal schema/migration and owner-private filesystem opening/backup behavior have
explicit private locality behind the existing Journal interface.

Owners: [architecture](../docs/ARCHITECTURE.md), [v0.2 release design](../docs/V0.2.md), and
[KAP-0038](../docs/experiments/KAP-0038-kubernetes-effect-gateway-boundary.md).

## Decision

Keep `Application`, Gateway lifecycle orchestration, Journal, receipt encoding/inspection, receipt
publication, and the concrete Kubernetes adapter as deep modules. Extract only independently
changing journal concerns that already sit behind the Journal interface:

```text
Gateway
  -> Journal
       -> opening
            -> schema
```

`opening` owns descriptor-relative durable entry, backup verification, rollback recovery, and Unix
file identity. `schema` owns exact current/legacy layouts, migration recognition, initialization,
and integrity checks. Both remain private children; callers cannot select storage, name SQL, or
sequence durable transitions.

## Rejected extractions

- Gateway orchestration remains cohesive because splitting it would spread lifecycle ordering.
- Receipt construction and parsing retain one exact-format owner.
- Receipt publication already has distinct private locality.
- One concrete Kubernetes adapter does not justify a provider seam.
- Test support remains private and does not create production interfaces.

## Evidence

Commit `d512b72` introduced the private `opening` and `schema` children without a trait, runtime
selection, public SQL, new crate, provider/storage adapter, or reverse dependency.

The v0.1.1 source-fixture matrix passed all historical states, migration/restore process-loss cases,
hot rollback, complete row/provider/backup/receipt comparison, candidate reopen, and old-source
downgrade reopen. Focused migration, lifecycle, recovery, grant, receipt, CLI, MCP, Clippy,
formatting, link, diff-hygiene, and default gates passed.

## Acceptance

- Journal callers retain the same deep interface.
- Exact migration, backup, restore, downgrade, grant, and receipt behavior remains byte-for-byte.
- No public Rust compatibility promise, crate, generic storage/provider interface, runtime plugin,
  second adapter, capability, or sandbox dependency appears.
- Each extracted private child passes the deletion test: removing it would move cohesive schema or
  filesystem/recovery knowledge back into Journal opening.

## Residual risk

Private moves can hide coupling that behavior tests do not expose. Future schema, receipt, or
capability changes may justify different locality; this record does not freeze the module tree.
