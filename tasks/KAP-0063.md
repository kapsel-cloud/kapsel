# Accept And Publish The v0.2 Beta

Status: complete. Public prerelease
[`v0.2.0`](https://github.com/kapsel-cloud/kapsel/releases/tag/v0.2.0) contains the exact accepted
five-asset set for candidate `5fe0407cd5ebd78f386905e33f79e0f712a57835`. Fresh public downloads
passed identity, authentication, artifact, upgrade, and live-kind verification. The website handoff
and KAP-0047 may now proceed against only this release.

Problem: a technically complete candidate is not a release until one exact revision, artifact set,
compatibility contract, residual-risk record, publication transaction, and downloaded verification
are independently accepted. The website also needs a claim-complete handoff rather than inferred
repository status.

Contract owners: [v0.2 release design](../docs/V0.2.md), [release artifacts](../docs/RELEASE.md),
[security policy](../SECURITY.md), the accepted KAP-0058 through KAP-0062 evidence, and the exact
KAP-0065 replacement-candidate evidence.

Depends on: exact KAP-0065 replacement candidate and its reconciled qualification, distribution, and
independent-review evidence. Explicit publication authorization remains the gate between accepted
rehearsal and the publication transaction.

## Acceptance

- Every review addresses the exact candidate and reports no unresolved blocker.
- The tag, release metadata, archive, sidecars, source revision, compatibility owner, and release
  notes agree exactly.
- Public assets match accepted local bytes and pass downloaded-artifact verification.
- `v0.1.0` and `v0.1.1` tags/assets remain unchanged.
- The website handoff can stand alone without private context or unpublished repository state.
- Public wording says developer beta, one Kubernetes operation, no production readiness, no
  exactly-once effect, explicit `UNKNOWN`, `INSPECTED` not `VERIFIED`, and sole supported target.
- KAP-0047 names the exact published beta as its evidence baseline.

## Non-goals

No automatic publication, crates.io, production launch, public sandbox, customer identity, pricing,
market conclusion, second capability, daemon, managed control plane, or post-beta implementation
backlog.
