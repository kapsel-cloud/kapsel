# Define The Finite v0.2.0 Release Unit

Status: complete and adopted. [`docs/V0.2.md`](../docs/V0.2.md) is the accepted implementation
direction selected by [KAP-0046](KAP-0046.md); it does not itself authorize publication.

Problem: the workspace version covers the published root artifact and unpublished support packages,
while CLI, MCP, Rust, grant, receipt, journal, sandbox, deployment, and hosted surfaces have
different owners and maturity. Treating workspace completion or sandbox completion as “v0.2.0” would
silently promote internal interfaces and unrelated cloud scope.

Direct owners: [technical scope](../docs/SCOPE.md), [V1 technical direction](../docs/VISION.md),
[v0.2 release design](../docs/V0.2.md), [release artifacts](../docs/RELEASE.md), and
[testing strategy](../docs/TESTING.md).

## Result

The reviewed design:

- defines one x86-64 GNU/Linux root `kapsel` archive as the release unit;
- keeps `kapsel-sandbox`, hosted deployment, repository tooling, fuzz packaging, private protocols,
  SQL, and speculative packages outside distribution compatibility;
- preserves the KAP-0038 authorization, durable attempt, receiver result, explicit `UNKNOWN`, frozen
  receipt, and inspection semantics;
- separates supported beta CLI/MCP/grant/receipt/artifact behavior from unsupported Rust and
  internal surfaces;
- requires exact `v0.1.1` journal, grant, and receipt continuity through a private migration and
  rollback proof;
- defines finite reliability, performance, security, supply-chain, documentation, and release gates;
  and
- leaves a resident process, another capability, crates.io, another target, and the sandbox behind
  their independent triggers.

Fresh architecture, compatibility, security, and release reviews found no blocker in the prospective
design. KAP-0046 then selected a maintainer-conviction Stabilize route, adopted the design, resolved
external evaluation as post-beta work, and instantiated the finite packet sequence.

## Acceptance

- One canonical owner names the product promise, release unit, supported and unsupported surfaces,
  ordered work, and release proof.
- Distributed root artifact and paused hosted sandbox remain separate.
- The design labels v0.2 a developer beta rather than production-ready or externally validated.
- Every implementation category has one bounded packet.
- No version, code, wire, schema, package, provider resource, or release tag changed in this design
  packet.

## Non-goals

No automatic release, Kubernetes operation suite, daemon, hosted control plane, provider deployment,
public Rust SDK, package extraction, customer record, or production-readiness claim.

## Next action

Implementation begins with [KAP-0058](KAP-0058.md). Preserve the packet order and do not combine the
lifecycle refactor with compatibility, migration, distribution, or publication work.

## Residual risk

The design is a deliberate maintainer technology bet rather than an external-demand conclusion.
Post-release KAP-0047 evidence decides whether another product cycle is justified.
