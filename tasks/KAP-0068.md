# Minimize Workspace Rust Interfaces

Status: post-release. The review may begin after verified publication; implementation remains
separate from release-tooling cleanup.

Problem: the root Rust interface is explicitly unsupported for external compatibility, but workspace
binaries, sandbox code, fuzzing, and integration tests still require broad public visibility.
`AgentRequest` is a shallow alias, receipt filesystem shape crosses the application interface, and
unsupported visibility has not been mapped item-by-item to real consumers.

Contract owners: [architecture](../docs/ARCHITECTURE.md), [v0.2 release design](../docs/V0.2.md),
and [V1 technical direction](../docs/VISION.md).

Depends on: verified v0.2.0 publication and retained CLI, MCP, migration, receipt, and sandbox
consumer tests.

## Work

- Map every `src/lib.rs` export to the ordinary binary, MCP, sandbox, fuzzing, integration tests, or
  a separately approved external consumer.
- Apply the deletion test to aliases and projection types; remove or justify `AgentRequest` rather
  than replacing it with a generic capability envelope.
- Grill whether `OperationReport` callers need local `ReceiptReference.path` or only bounded
  publication identity before changing that interface.
- Move test-only visibility behind private test seams when black-box evidence does not require a
  public item.
- Preserve `Application` as the deep caller interface and keep lifecycle sequencing private.
- Keep CLI, MCP, and sandbox framing distinct and retain one concrete production Kubernetes adapter.

## Acceptance

- Every public item has a named real consumer and reason for visibility.
- Shallow aliases and test-only exposure are removed or explicitly justified.
- Filesystem receipt details cross the Application seam only where crash recovery or a real consumer
  requires them.
- CLI/MCP black-box parity, sandbox deletion/build proof, fuzzing, retained receipt inspection, and
  application contract tests pass.
- No public Rust compatibility promise, crates.io package, generic provider, transport, protocol,
  receipt, or storage interface appears.

## Non-goals

No second capability, daemon, public SDK, package extraction, receipt-format change, lifecycle
redesign, or visibility churn solely to reduce an item count.

## Next action

After publication, produce the consumer-to-export inventory and grill receipt-path exposure before
editing interfaces.

## Residual risk

Reducing visibility can weaken black-box evidence or break the real sandbox consumer even where
external Rust compatibility is unsupported. Keep process tests at supported interfaces and use the
sandbox deletion/build gate for every root-interface change.
