# Minimize Workspace Rust Interfaces

Status: deferred. Sandbox deletion is complete; interface minimization now waits for a real resident
consumer or observed product blocker.

Problem: the root Rust interface is explicitly unsupported for external compatibility, but workspace
binaries, fuzzing, and integration tests still require public visibility. `AgentRequest` is a
shallow alias, receipt filesystem shape crosses the application interface, and unsupported
visibility has not been mapped item-by-item to real consumers.

Contract owners: [architecture](../docs/ARCHITECTURE.md), [v0.2 release design](../docs/V0.2.md),
and [V1 technical direction](../docs/VISION.md).

Depends on: verified v0.2.0 publication, completed sandbox deletion, and retained CLI, MCP,
migration, receipt, fuzz, and application-contract tests.

## Work

- Map every `src/lib.rs` export to the ordinary binary, MCP, fuzzing, integration tests, or a
  separately approved external consumer.
- Apply the deletion test to aliases and projection types; remove or justify `AgentRequest` rather
  than replacing it with a generic capability envelope.
- Grill whether `OperationReport` callers need local `ReceiptReference.path` or only bounded
  publication identity before changing that interface.
- Move test-only visibility behind private test seams when black-box evidence does not require a
  public item.
- Preserve `Application` as the deep caller interface and keep lifecycle sequencing private.
- Keep CLI and MCP framing distinct and retain one concrete production Kubernetes adapter.

## Acceptance

- Every public item has a named real consumer and reason for visibility.
- Shallow aliases and test-only exposure are removed or explicitly justified.
- Filesystem receipt details cross the Application seam only where crash recovery or a real consumer
  requires them.
- CLI/MCP black-box parity, fuzzing, retained receipt inspection, and application contract tests
  pass.
- No public Rust compatibility promise, crates.io package, generic provider, transport, protocol,
  receipt, or storage interface appears.

## Non-goals

No second capability, daemon, public SDK, package extraction, receipt-format change, lifecycle
redesign, or visibility churn solely to reduce an item count.

## Activation trigger

Remain deferred. KAP-0054 may inventory exports while choosing a composition, but interface edits
require its accepted route or retained use to name a real consumer and measured friction. Do not
perform visibility churn in parallel with the resident decision merely because sandbox deletion made
items removable.

## Residual risk

Reducing visibility can weaken black-box evidence even where external Rust compatibility is
unsupported. Keep process tests at supported interfaces, and make only consumer-driven changes.
