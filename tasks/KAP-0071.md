# Prove One Optional Nix Development Environment

Status: deferred. KAP-0070 and KAP-0073 have closed; KAP-0054 owns the product route. Begin only
from accepted resident-pilot evidence, accepted Grafik flake-pilot evidence, or a separate
maintainer reprioritization.

Problem: Kapsel names exact Rust, Node, Python, Prettier, and cargo-make prerequisites, but a new
checkout still requires host-specific installation and PATH composition. A repository-local Nix
flake may reduce setup drift without becoming a second build, qualification, release, or product
interface. That value has not been proved against Kapsel's complete deterministic gate or supported
development hosts.

Direct owner: [Build](../docs/BUILD.md). Release assembly remains owned by
[Release artifacts](../docs/RELEASE.md), and the active product route is owned by
[KAP-0073](KAP-0073.md) and [KAP-0054](KAP-0054.md).

Depends on: accepted resident-pilot evidence, managed direnv/nix-direnv workstation integration for
automatic activation, and accepted evidence from Grafik's focused flake development-environment
pilot unless a maintainer explicitly authorizes Kapsel-first evaluation.

## Finite result

One optional repository-local flake supplies the prerequisites for the existing deterministic,
containerless default gate on Apple Silicon macOS and x86-64 Linux. A reviewed `.envrc` may activate
that shell automatically. `rust-toolchain.toml`, `Cargo.lock`, `Makefile.toml`,
`scripts/ci-local.sh`, and `docs/BUILD.md` retain their current jobs; Nix does not redefine the
gate, release target, qualification evidence, or installed product.

## Work

1. Add a minimal `flake.nix`, committed `flake.lock`, and `.envrc`; use `use flake` and disable
   nix-direnv's last-known-good fallback so an invalid environment fails visibly.
2. Derive or validate Rust `1.96.1`, Clippy, and rustfmt from `rust-toolchain.toml` rather than
   introducing an independent toolchain owner.
3. Supply the ordinary default-gate prerequisites: cargo-make, Node.js 24, Prettier exactly `3.6.2`,
   and Python 3.11 or later. Keep every version statement synchronized with `docs/BUILD.md` and
   hosted CI.
4. Expose development shells for `aarch64-darwin`, `aarch64-linux`, and `x86_64-linux`, while making
   native acceptance mandatory only where the project currently claims a development or release
   lane.
5. Run the existing gate inside `nix develop`; do not translate Make tasks or shell scripts into Nix
   checks merely to duplicate their truth.
6. Keep the non-Nix setup and hosted CI working. CI may add a small flake-evaluation lane only after
   the local pilot proves that its maintenance and runtime cost are bounded.
7. Update `docs/BUILD.md` in the same change and explicitly distinguish an optional developer shell
   from the pinned x86-64 release builder, live-kind prerequisites, qualification baseline, and
   customer-facing artifact.
8. Record cold/warm activation, store use, and any cache dependency as developer-environment
   observations rather than build-performance or reproducibility claims.

## Acceptance

- `nix flake check` evaluates every declared development-shell output without replacing the default
  repository gate.
- `nix develop --command ./scripts/ci-local.sh` passes from a clean checkout on Apple Silicon macOS
  and x86-64 Linux.
- `./scripts/ci-local.sh` continues to pass through the documented non-Nix setup.
- Tool version output matches `rust-toolchain.toml`, `docs/BUILD.md`, and
  `.github/workflows/ci.yml`.
- `.envrc` requires explicit `direnv allow`, requires approval after modification, and cannot retain
  a prior shell after flake evaluation fails.
- Default-gate commands use no sibling checkout, project-global mutable state, private cache,
  credential, provider, Docker daemon, or live Kubernetes cluster.
- Release artifact, SBOM, reproducibility, upgrade, qualification, and live-kind bytes and commands
  remain unchanged unless their direct owners separately authorize a later change.
- Removing the three Nix files restores the prior supported setup without product, journal, receipt,
  CLI, MCP, sandbox, or release migration.

## Non-goals

No devenv, lorri daemon, shared cross-repository flake, hosted binary cache, Nix-based release
rewrite, NixOS deployment module, customer installation path, qualification shortcut, provider
selection, sandbox deployment, public traffic, second capability, or reproducible-build claim from a
passing development shell.

## Residual risk

Nix input locking does not make macOS and Linux outputs byte-identical, remove ambient host
services, or prove the release artifact. Exact packaging of Prettier and the Rust toolchain may add
more update work than the shell removes. Docker, kind, kubectl, cargo-fuzz, Cosign, Trivy, provider
authority, and live resources remain separately owned prerequisites and gates. Delete the optional
path if it cannot remain smaller than the setup it replaces.
