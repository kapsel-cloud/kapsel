# Evaluate An Optional Nix Development Shell

Status: deferred. The current documented toolchain remains the supported development path.

Problem: a Nix shell might reduce local tool-version drift, but it must not become a second release
builder, deployment format, or required contributor path without measured benefit.

Owners: [build guide](../docs/BUILD.md), [release artifact contract](../docs/RELEASE.md), and
[contributor guide](../AGENTS.md).

## Activation trigger

Begin only when a reproducible local setup failure cannot be fixed more simply in the existing
setup, lockfiles, or scripts.

## Acceptance

- One `flake.nix` and lock file provide the documented Rust and repository tools.
- `nix develop` runs the ordinary format, test, Clippy, rustdoc, and documentation gates unchanged.
- Non-Nix setup and hosted CI remain supported.
- The shell does not replace the pinned x86-64 release builder or live-kind prerequisites.
- Cold/warm activation and store use are measured.
- No hosted binary cache, NixOS deployment module, release rewrite, or installation claim is added.

## Residual risk

The shell adds another dependency lock and maintenance surface. Delete it if it does not measurably
reduce setup drift or if it diverges from the release builder.
