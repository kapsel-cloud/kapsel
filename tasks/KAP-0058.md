# Unify The Production Lifecycle Path

Status: complete and independently reviewed. Production, deterministic faults, simulations, and
subprocess crash tests now cross one private operation-selected provider lifecycle and one private
operation-selected receipt lifecycle.

Problem: `Gateway` currently has operation-selected production paths and separate queue-selected
fault-test paths for provider execution and receipt finalization. Tests can therefore prove a nearby
implementation rather than the exact implementation used by `Application`, reducing locality at the
most important crash seams.

Contract owners: [KAP-0038](../docs/experiments/KAP-0038-kubernetes-effect-gateway-boundary.md),
[architecture](../docs/ARCHITECTURE.md), [testing](../docs/TESTING.md), and
[v0.2 release design](../docs/V0.2.md).

Depends on: completed Stabilize decision [KAP-0046](KAP-0046.md).

## Work

- Inventory every production, deterministic-fault, subprocess, simulation, and demo call path
  through provider execution and receipt finalization.
- Add or adjust tests first so every crash point addresses the same exact operation-selected private
  implementation used by `Application`.
- Collapse duplicate queue-selected and operation-selected algorithms into one implementation per
  lifecycle responsibility.
- Keep fault controls private and compile-time/test scoped; they may decorate the production path
  but cannot become caller, command, MCP, configuration, or receipt input.
- Preserve worker exclusion, fair transient-read deferral, exact operation selection, transition
  ordering, receiver classification, frozen receipt bytes, and publication recovery.
- Delete obsolete helpers and update architecture documentation only where implementation ownership
  actually changes.

## Acceptance

- The deletion test removes duplicate lifecycle algorithms without moving their complexity into
  callers.
- Production, deterministic fault, simulation, subprocess, and demo tests cross the same private
  lifecycle implementation.
- Every owned pre-attempt, mutation, observation, receipt preparation, publication, and finalization
  crash point remains covered.
- Recovery after `apply_started` performs no second mutation.
- Frozen receipt bytes, path, digest, and key identity remain unchanged across restart.
- Public Rust exports, CLI, MCP, grant, receipt wire, journal schema, and artifact layout are
  unchanged.
- Focused lifecycle and subprocess tests, root package Clippy, the default repository gate, and
  fresh architecture/correctness review pass.
