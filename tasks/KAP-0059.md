# Adopt The Beta Interfaces And Deepen Application

Status: complete and independently reviewed. Exact v0.2.x beta interfaces are adopted; `Application`
and the private CLI/MCP support seam now own the reduced workspace surface.

Problem: `Application::execute` is deep, but the root Rust surface also exposes lifecycle stages,
low-level errors, and filesystem receipt shape. CLI and MCP are two real transport adapters, yet MCP
reaches through the command module for operator composition and both adapters duplicate domain
projection. v0.2 needs explicit supported beta interfaces and better locality without creating a
generic protocol or provider seam.

Contract owners: [v0.2 release design](../docs/V0.2.md), [architecture](../docs/ARCHITECTURE.md),
[evaluator commands](../docs/COMMANDS.md), [MCP](../docs/MCP.md), KAP-0038, and
[security policy](../SECURITY.md).

Depends on: accepted KAP-0058 lifecycle implementation.

## Work

- Adopt exact v0.2.x compatibility wording and vectors for the CLI, MCP adapter, grant v1
  acceptance, retained receipt v2 inspection, result vocabulary, bounds, diagnostics, and error
  classes.
- Keep the Rust package and crates.io unsupported for external consumers; retain only public Rust
  exposure required by real workspace callers and tests.
- Preserve `kapsel-sandbox -> kapsel` without moving sandbox behavior into the root package.
- Concentrate shared operator-configuration loading and domain report/error projection behind one
  private seam used by the CLI and MCP adapters.
- Keep command grammar, MCP framing/lifecycle, and transport-specific output inside their respective
  adapters.
- Remove sibling transport leakage and duplicate domain mappings where one private owner can express
  them without forcing identical transport envelopes.
- Update `COMMANDS.md`, `MCP.md`, `ARCHITECTURE.md`, `SECURITY.md`, and KAP-0038 only for decisions
  they directly own.

## Acceptance

- Every supported and unsupported v0.2 surface is explicit and consistent with `docs/V0.2.md`.
- `Application` remains one deep compile-time module; callers cannot sequence unsafe durable states
  or provide authority through request input.
- The CLI and MCP adapters cross one shared private composition/projection seam and retain distinct
  framing.
- Exact CLI and MCP result/rejection/error parity is proven through black-box production processes.
- Grant v1 and receipt v2 canonical vectors remain byte-compatible with `v0.1.1`.
- The ordinary root package still builds after deleting `kapsel-sandbox`; the sandbox still builds
  as a one-way consumer.
- No crates.io/docs.rs promise, generic envelope, provider interface, second capability, or runtime
  plugin appears.
- Focused application/CLI/MCP/sandbox-consumer tests, Clippy, default gate, and fresh architecture,
  compatibility, and security review pass.

## Non-goals

No journal migration, release packaging, new MCP transport, remote endpoint, SDK, daemon, sandbox
resumption, version bump, or publication.
