# Qualify The v0.2 Beta

Status: queued after [KAP-0064](KAP-0064.md).

Problem: clean architecture and migration proof do not establish bounded behavior under hostile
input, repeated recovery, supported-environment variance, dependency failure, or resource pressure.
The beta needs finite measured stopping rules rather than a broad production-readiness program.

Contract owners: [v0.2 release design](../docs/V0.2.md), [testing](../docs/TESTING.md),
[threat model](../docs/THREAT_MODEL.md), [security policy](../SECURITY.md), and KAP-0038.

Depends on: one lifecycle implementation, adopted beta interfaces, accepted migration behavior, and
accepted root release-source locality.

## Work

- Inventory every root `kapsel` production input, filesystem, trust, provider, migration, receipt,
  and transport denial surface and bind it to deterministic or fuzz evidence.
- Inventory owner-local constants and derived limits within the root v0.2 release behavior; add
  compile-time assertions for internal relationships while preserving typed runtime rejection for
  hostile input. Create a shared private limits module only where qualification proves one genuinely
  shared contract.
- Run seeded lifecycle simulation and real subprocess recovery across the unified implementation and
  migration seams.
- Exercise healthy, failed-rollout, and bounded-unknown live-kind paths with owned cleanup.
- Define finite performance environments, sample counts, failure ceilings, percentiles/maxima, and
  budgets before measuring.
- Measure startup, grant provisioning, journal open/submit/reconcile, target read, patch request,
  observation wait, receipt construction/publication/inspection, restart/recovery, peak RSS, CPU,
  journal/receipt growth, and artifact-size inputs.
- Keep local implementation time separate from Kubernetes waiting; no timeout may become receiver
  `FAILED` or hide `UNKNOWN`.
- Review dependency, key/trust, filesystem, disclosure, and vulnerability posture for one frozen
  qualification-baseline source revision.
- Record the baseline revision, executable/source digests, gate inputs, budgets, and the exact
  non-executable or version-identity deltas KAP-0062 may introduce before every affected gate must
  be rerun.

## Acceptance

- All production hostile-input interfaces have bounded owner-specific proof and no unresolved
  release blocker.
- Every security, compatibility, and resource bound in the root v0.2 release behavior is named,
  enforced at runtime where externally influenced, and compile-time checked where related constants
  encode an internal invariant. Wire-format, adapter, and storage constants remain with their owners
  unless shared semantics are explicitly established; externally observable changes update their
  direct contract owners.
- Seeded simulation and subprocess matrices print exact replay inputs and preserve mutation/receipt
  invariants.
- Live-kind healthy, failed, and unknown paths preserve one-attempt and cleanup evidence.
- Every performance result records environment, revision, state/input class, sample/failure count,
  and selected percentile or maximum.
- Candidate budgets pass without becoming public production or latency promises.
- Security review records supported beta posture, no-SLA limits, dependency findings, exceptions,
  owners, and expiry.
- Default, fuzz, simulation, demo, and live-kind lanes plus fresh reliability, performance, privacy,
  and security review pass.
- One qualification manifest binds all evidence to the baseline revision and states that it is not
  release-candidate evidence until KAP-0062 reconciles and reruns it against the exact candidate.

## Non-goals

No coverage-percentage gate, benchmark marketing claim, production SLO, compliance claim, another
platform, provider, capability, hosted load test, or release publication.

## Next action

Record exact accepted budgets, qualification manifest, permitted candidate deltas, and residual
risks, then hand them to [KAP-0062](KAP-0062.md) for exact-candidate reconciliation.

## Residual risk

Disposable kind and one x86-64 environment cannot establish production-cluster behavior. The beta
must state that limit and avoid converting measured local behavior into universal support claims.
