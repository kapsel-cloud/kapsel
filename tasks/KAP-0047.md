# Run The Bounded v0.2 Beta Evidence Cycle

Status: supporting evidence owner for exact public developer-beta release
[`v0.2.0`](https://github.com/kapsel-cloud/kapsel/releases/tag/v0.2.0), source revision
`5fe0407cd5ebd78f386905e33f79e0f712a57835`, and archive SHA-256
`82db38b05772b1b6a4ef9a9312baf9633f0ce652ddfe8052ed7df86d1fd1d969`.

Problem: repository proof can establish correctness claims for an exact artifact, but it cannot show
whether independent Kubernetes practitioners understand the proposition, complete an integration, or
choose it for a real workflow. The local evaluator remains a rigorous reference and regression path;
completing an evaluator cohort is not a prerequisite for the active bounded product proof. This
packet owns only approved aggregate technical findings from exact-artifact evaluation and later
product-preview use.

Contract owners: [technical scope](../docs/SCOPE.md), [v0.2 release design](../docs/V0.2.md),
[evaluator guide](../docs/EVALUATOR.md), [testing strategy](../docs/TESTING.md), and

Depends on: an exact published v0.2.x artifact accepted by [KAP-0063](KAP-0063.md). The hosted
sandbox is retired and contributes no cohort. Private recruitment, identities, interview records,
continuation thresholds, positioning, and company decisions remain outside this repository.

## Baseline disposition

The exact `v0.1.1` artifact remains immutable release history and may still be evaluated, but no
independent `v0.1.1` cohort is required to authorize v0.2. No run is fabricated or reclassified as
external evidence. Existing release rehearsals remain maintainer-operated technical proof.

## Work

- Distribute and evaluate the exact accepted v0.2.x artifact on its named supported target and only
  in non-consequential environments.
- Record only approved aggregate technical facts: completion outcomes, setup friction, maintainer
  support burden, result comprehension, reproducible defects, repeated evaluation, and concrete
  integration constraints.
- Distinguish independent completion, support-assisted completion, abandonment, reproducible defect,
  comprehension failure, and voluntary repeated use.
- Separate correctness, security, documentation, packaging, and compatibility defects from feature
  requests.
- Open a finite defect packet before changing released behavior; do not mutate a published tag.
- Treat requests for another operation as evidence for one coherent workflow, never as automatic
  capability or generic-interface authorization.
- Publish only the aggregate technical result needed to select the next route.

## Acceptance

- Every counted run identifies the exact beta version and supported environment without publishing
  evaluator identity or private operational data.
- Aggregate evidence distinguishes unassisted, support-assisted, abandoned, defective,
  misunderstood, and repeated-use outcomes.
- Any security or correctness finding follows the disclosure and owner route before evaluation
  resumes.
- The final record either supports one explicit next technical route or states that evidence was
  insufficient.
- No production credential, consequential cluster, private workflow record, second capability,
  generic provider seam, or hosted dependency enters the public evidence.
