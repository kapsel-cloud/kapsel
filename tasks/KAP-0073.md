# Remove The Hosted Sandbox

Status: complete. The deployable sandbox implementation and its active gates were removed. Fixed
fixtures, historical contracts, and archive tags remain for engineering reference.

Direct owners: [technical scope](../docs/SCOPE.md), [architecture](../docs/ARCHITECTURE.md),
[testing](../docs/TESTING.md), [build](../docs/BUILD.md), and [KAP-0070](KAP-0070.md). KAP-0038
continues to own authorization, lifecycle, receiver result, `UNKNOWN`, and receipt semantics.

## Decision

Preserve:

- the root `kapsel` package and `Application` interface;
- authorization and caller/operator authority separation;
- durable operation identity and pre-attempt facts;
- conditional Kubernetes mutation and observation-only recovery;
- receiver-bounded `SUCCEEDED`, `FAILED`, and `UNKNOWN`;
- frozen signed receipts and offline inspection;
- the CLI, fixed stdio MCP adapter, process-loss harness, disposable-`kind` demonstration, release
  evidence, fixtures, and compatibility contracts; and
- historical sandbox contracts and exact archive tags.

Remove:

- anonymous HTTP admission and reconnectable projection;
- abuse-edge and public-traffic composition;
- synthetic-cluster scheduling and capacity;
- runner-host identities, cgroups, descriptor handoff, and authority generations;
- sandbox-specific policy, cleanup inventory, and host bundle;
- provider/deployment gates; and
- the unpublished `kapsel-sandbox` package and deployable assets.

Sandbox runner, staging, scheduler, cleanup, transport, provider, and storage code must not move
into root `kapsel` or the resident package.

## Removed surfaces

The deletion removed:

- `crates/kapsel-sandbox` and `deploy/sandbox`;
- every `test-sandbox-*` script and Make task;
- sandbox workspace, lockfile, feature, fixture-lane, and dependency wiring; and
- active build, testing, architecture, threat, privacy, release, and routing claims that depended on
  a deployable sandbox.

Post-deletion Cargo metadata reports only the root product and repository tooling packages. Root
application, CLI, MCP, process-loss, receipt, workspace, Clippy, rustdoc, documentation, formatting,
link, and default gates pass.

## Preserved evidence

Annotated tag `archive/kap-0070-final-narrowed-sandbox-0579660` preserves the final narrowed
implementation. Tag `archive/kap-0070-backup-restore-bde1e3b` preserves the earlier backup/restore
checkpoint. Neither is an active deployment route.

`docs/fixtures/sandbox-v1` remains a small historical explanation of the removed HTTP contract. The
unavailable-image receipt remains an input to root offline-inspection tests because it is valid
classifier-complete KAP-0038 evidence. The historical API and deployment documents carry no active
validator, support, or compatibility promise.

## Acceptance

- No deployable sandbox package, asset, build lane, or dependency remains in the active workspace.
- Root KAP-0038 behavior, release compatibility, process-loss evidence, and local disposable-cluster
  demonstration remain intact.
- Historical fixtures and archive tags are clearly non-deployable.
- No sandbox topology or interface is a current compatibility surface.

## Residual risk

Release assembly was not repeated during deletion because Docker was unavailable. The source and
artifact tests were unchanged, but workspace removal changed `Cargo.lock` and therefore the release
metadata graph. Later v0.2.0 candidate work rebuilt and verified the published artifact from the
updated workspace.
