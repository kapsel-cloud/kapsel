# Decide And Deepen Or Retire The Sandbox

Status: conditional. Begin only after explicit authorization to decide whether the sandbox resumes,
remains preserved but paused, or retires while keeping accepted evidence.

Problem: the paused `kapsel-sandbox` package contains more than half of the repository's Rust lines.
Its large library combines admission, dispatch and leases, application projection, HTTP, receipt
publication and retention, database opening and migration, and public reads behind a broad
workspace-visible interface. Refactoring it before deciding whether the program resumes would spend
release attention on excluded scope.

Contract owners: [public sandbox API](../docs/SANDBOX_API.md),
[sandbox deployment](../docs/SANDBOX_DEPLOYMENT.md), [architecture](../docs/ARCHITECTURE.md), and
[V1 technical direction](../docs/VISION.md).

Depends on: explicit authorization to make the sandbox continuation, preservation, or retirement
decision. Verified v0.2.0 publication does not itself activate this packet.

## Work

- Decide whether the sandbox resumes, remains preserved but paused, or retires.
- If resumed, reassess `crates/kapsel-sandbox/src/lib.rs` by independent change axis and deletion
  test rather than line count.
- If resumed, deepen private HTTP projection and private database opening/schema/migration locality
  where deleting either child would move cohesive policy back into `Service`.
- Reduce public visibility created only by package binaries and integration tests while preserving
  real process and contract evidence.
- Preserve the one-way `kapsel-sandbox -> kapsel` dependency and separate admission/projection
  state.
- If paused or retired, reduce sandbox prominence in active contributor/build/testing navigation and
  decide whether full preservation tests remain in the default gate or a separately owned lane.
- Preserve accepted KAP-0051 through KAP-0056 evidence without presenting it as v0.2 release scope.

## Acceptance

- One explicit decision owns continuation, preservation, or retirement.
- A resumed sandbox has deep private locality for independently changing HTTP and durable-store
  concerns without generic provider, storage, or transport interfaces.
- A paused or retired sandbox no longer dominates the active release route, while accepted evidence
  and reproducible preservation checks remain findable.
- The root release package builds after deleting the sandbox and no reverse dependency appears.
- No provider selection, deployment, spend, credentials, endpoint, DNS, or public traffic is
  authorized by this packet alone.

## Non-goals

No automatic sandbox deployment, v0.2 release dependency, generic hosted platform, provider
selection, second capability, or refactor justified only by physical line count.

## Next action

Keep this packet conditional until a separate scope decision selects continuation, preservation, or
retirement.

## Residual risk

Leaving a large paused package in the default workspace increases navigation and maintenance cost;
removing it from routine gates can allow accepted evidence to rot. The eventual decision must choose
that tradeoff explicitly rather than inheriting it accidentally.
