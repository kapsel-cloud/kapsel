# Historical Serialized Sandbox Topology

Status: superseded. This design narrowed the hosted sandbox to one active run before KAP-0070 closed
through offline fallback and KAP-0073 removed the implementation.

Owners: [historical sandbox API](../docs/SANDBOX_API.md),
[historical sandbox deployment](../docs/SANDBOX_DEPLOYMENT.md), and [sandbox removal](KAP-0073.md).

## Decision

The selected historical topology serialized admission, execution, retention handoff, and cleanup:

```text
fixed HTTP admission/projection
  -> one active run
       -> native runner process
            -> one synthetic Kubernetes target
                 -> receipt projection
                      -> cleanup and absence evidence
```

The controller host and synthetic cluster were separate. The host held one owner-private durable
volume and one writer for admission and immutable receipt state. The cluster held only synthetic
targets and fixed policy; it contained no controller database, receipt store, or signing store.

## Preserved properties

- fixed request and projection schemas;
- one-active capacity with fail-closed saturation;
- separate runner identity and descriptor handoff;
- durable invocation marker and same-operation recovery;
- fixed authority staging and dispatch pins;
- provider-neutral synthetic-cluster policy;
- bounded receipt retention; and
- cleanup completion only after owned-resource absence.

## Rejected additions

The design rejected concurrent runs, generic provider/storage/queue interfaces, broad Kubernetes
input, managed credentials, a dashboard, and a second capability. Backup/restore and
replacement-host continuity were later removed by KAP-0072.

## Closure

No provider or public-exposure gate completed. Historical source and archive tags preserve the
offline design, but no controller, provider inventory, host bundle, image, endpoint, or traffic path
is active. The topology must not be reused as the resident-service architecture.

## Residual risk

The serialized design never established complete live isolation, availability, provider teardown,
public abuse resistance, or disaster recovery.
